# dogking-tools

![License](https://img.shields.io/badge/license-MIT-blue)
![ComfyUI](https://img.shields.io/badge/ComfyUI-custom%20node-green)
![Python](https://img.shields.io/badge/python-3.10%2B-yellow)

ComfyUI 提示词/图片批量加载节点。读 PromptVault（或任何工具）导出的 `.txt` / `.csv`，
按行输出提示词；也可以按顺序读一整个文件夹的图片，配合自动排队实现
**一条提示词（或一张图）跑一遍完整工作流**。

另外还有 4 个 **PromptVault 数据源节点**，不用导出文件，直接从 PromptVault 桌面应用实时拉
提示词 / 图片 / 词库（见下方「节点：PromptVault 数据源」）。

---

## 安装

把整个 `dogking-tools` 目录放进 ComfyUI 的 `custom_nodes/`，重启 ComfyUI 即可。

```
ComfyUI/custom_nodes/dogking-tools/
```

两种装法：

```bash
# ① git clone（后续 git pull 就能更新）
cd ComfyUI/custom_nodes
git clone https://github.com/liao942287300-cyber/dogking-tools.git
```

② 从 [Releases](https://github.com/liao942287300-cyber/dogking-tools/releases/latest) 下 `dogking-tools-x.x.x.zip`，
解压到 `custom_nodes/` 下，**目录名保持 `dogking-tools`**（改成别的名字也行，但插件更新时容易搞混）。

没有第三方依赖，不需要 `pip install`。装完要**重启 ComfyUI**，只刷新网页不够 —— Python 节点要重新导入。

「选择文件」按钮在 Windows 上用 `ctypes` 直接调系统 `comdlg32.GetOpenFileNameW`，
**不依赖 tkinter** —— ComfyUI 的 `python_embeded` 是精简版，本身不带 tkinter。

## 节点

分类：`dogking-tools` → **提示词批量加载（dogking-tools）**

### 输入

| 参数 | 说明 |
| --- | --- |
| **文件路径** | `.txt` 或 `.csv` 的路径。点下方「选择文件」按钮弹系统选择框；也可以直接填。相对路径按 `ComfyUI/input` 解析 |
| **模式** | 全部生成 / 范围选取 / 编号选择 |
| **起始行** | 仅范围模式显示 |
| **结束行** | 仅范围模式显示，填 `0` 表示到最后一行 |
| **编号** | 仅编号模式显示 |
| **自动连续** | 打开后每生成完一张自动排下一行，直到跑完 |
| **重置计数** | 一次性按钮，点一下立即清零（不需要执行工作流，也不影响后续执行） |

> 参数会跟着模式变：选「全部生成」时只留文件路径 / 模式 / 自动连续，
> 选「范围选取」才出现起止行，选「编号选择」才出现编号。节点高度自动收缩。
> 「重置计数」是按钮，任何模式下都显示。

### 输出

| 输出 | 说明 |
| --- | --- |
| **提示词** | 当前行的提示词文本，接 CLIP Text Encode |
| **当前行号** | 第几行 |
| **总行数** | 文件一共几行 |
| **状态** | 例如 `第 3/100 行（全部生成 1-100）` |

节点底部会实时显示计数器，**中断或手动停止后一眼能看到跑到第几行**。

## 三种模式

### 全部生成

从第 1 行跑到最后一行。每执行一次输出一行，计数器 +1，跑完后归零。

配合「自动连续」打开，点一次运行就能把整个文件跑完。

### 范围选取

只跑指定的行区间。

- 填 `20` → `40`，跑第 20 到 40 行
- **填 `40` → `20` 会自动纠正成 20-40**，不用管顺序
- 数值超过总行数时按总行数处理（比如文件只有 50 行，填 `1` → `999` 就是 1-50）

### 编号选择

固定输出第 N 行，**不递增**。每次执行都是同一行，适合反复调试同一条提示词。

---

## 自动连续怎么工作

节点每执行完一次，如果这个范围还没跑完，会通知前端排下一次队列。
前端在 `execution_success` 之后才排，避免队列错乱。

**手动停止（Interrupt）或报错时不会继续排**，计数器停在当前行，下次点运行从这里接着跑。

## 文件格式

### txt

一行一条，空行自动跳过：

```
画面风格：电影级超写实摄影风格，核心元素：年轻东亚女性角色。
画面风格：现代都市街拍风格，核心元素：白色衬衫与黑色阔腿裤。
```

### csv

优先按表头找「提示词 / positive / prompt」列；没有表头就用**第 3 列**
（兼容 PromptVault 导出的 `序号,名称,正向提示词`）：

```csv
序号,名称,正向提示词
1,pic0,画面风格：电影级超写实摄影风格……
2,pic1,画面风格：现代都市街拍风格……
```

## 节点：Ripple 二采放大（dogking-tools）

配合 `ComfyUI-WepeNerd` 的 H3 Ripple 用：把 Ripple Clip 输出的 `ripple` 整体放大到二采尺寸，
**不用改第三方插件**。

```
Ripple Clip (ripple) → Ripple 二采放大 → Ripple Apply (ripple)
```

### 输入

| 参数 | 说明 |
| --- | --- |
| **ripple** | 接 H3 Ripple Clip 的 `ripple` 输出 |
| **模式** | `按倍数` / `按二采像素`。切到哪个模式，就只显示那个模式用的尺寸参数，另一个自动收起 |
| **放大倍数** | 按倍数模式：画布宽高 × 系数，默认 2 |
| **目标百万像素** | 按二采像素模式：跟二采流里的数学表达式一致，`ceil(sqrt(百万*1e6*宽/高)/32)*32` |
| **放大算法** | lanczos / bicubic / bilinear / area / nearest-exact |

### 输出

| 输出 | 说明 |
| --- | --- |
| **ripple** | 放大后的 ripple，宽高和 geometry 都改好了，直接接 Ripple Apply |
| **画面** | 放大后的窗口画面（含模型留边） |
| **宽度 / 高度** | 放大后的画布尺寸，一定是 32 的倍数 |

### 注意

- 画布宽高向上取 32 的倍数；内容区域按同比例放大，**留边比例不变**，构图不会歪。
- Ripple Apply 会按新的宽高建空 latent，guide 关键帧也用放大后的画面，二采不会尺寸对不上。
- 2 倍放大 = 4 倍像素。300 帧以上再 2 倍会明显吃内存，窗口短一点更稳。
- 跑完之后节点底部会显示这行：`480×864 → 768×1408（内容 768×1388）`。箭头前是原画布，箭头后是放大后的画布（喂给采样器、32 的倍数），括号里是画布中的**有效画面** —— Ripple Apply 提示里报的 `(768×1388)` 就是这个数。
- 宽高是各自向上取 32 的倍数，所以宽比和高比不一定完全相同（比如 768/480 = 1.60，1408/864 = 1.63），这是对齐导致的，不是算错。

## 节点：图片批量加载（dogking-tools）

分类：`dogking-tools` → **图片批量加载（dogking-tools）**

跟提示词节点同一套机制，只是数据源换成图片：每执行一次输出一张图，
`自动连续` 打开时前端会在本次执行结束后自动排下一次队列，直到跑完整个范围。

### 输入

| 参数 | 说明 |
| --- | --- |
| **文件夹路径** | 图片文件夹的完整路径。点下方「选择文件夹」按钮弹系统原生目录选择框；也可以直接填。相对路径按 `ComfyUI/input` 解析 |
| **排序方式** | `数字升序`（自然排序，`img2.png` 排在 `img10.png` 前面）/ `字母升序`（按文件名 a-z） |
| **模式** | `全部模式` / `范围模式` |
| **起始序号** | 仅范围模式显示 |
| **结束序号** | 仅范围模式显示，填 `0` 表示到最后一张 |
| **自动连续** | 打开后每跑完一张自动排下一张 |
| **手动列表** | 前端拖拽区自动写入（节点上隐藏，用户看不到）。想清空拖拽区就点缩略图上的 × |
| **重置计数** | 一次性按钮，点一下立即清零 |

> 参数会跟着模式变：选「全部模式」只留文件夹路径 / 排序方式 / 自动连续，
> 选「范围模式」才出现起止序号。节点高度自动收缩。

### 输出

| 输出 | 说明 |
| --- | --- |
| **图片** | 当前这张图，`[1, H, W, 3]` float32，值域 0-1，直接接 VAE Encode 之类的节点 |
| **当前序号** | 第几张（从 1 开始） |
| **总数量** | 这批一共几张 |
| **状态** | 例如 `第 3/100 张（全部模式 1-100）`、`第 3/100 张（范围模式 2-40）` |

节点底部会实时显示状态条，**中断或手动停止后一眼能看到跑到第几张**。

### 两种图片来源

1. **文件夹** —— 扫描文件夹里的 `.png / .jpg / .jpeg / .webp / .bmp / .gif / .tif / .tiff`，按排序方式排好
2. **拖拽** —— 把图片拖到节点的拖拽区，会自动上传到 `ComfyUI/input` 并追加在**文件夹扫描结果之后**（同一张图不会重复）

两种可以同时用：选一个文件夹，再额外拖几张图进来，一起按顺序跑。
排序只作用于文件夹扫描出来的那部分，拖进来的图保持拖入顺序。

拖拽区顶部显示 `共 N 张，当前第 M 张`，中间是缩略图网格，每张右上角的 × 可以移除。

### 范围模式

- 填 `20` → `40`，跑第 20 到 40 张
- **填 `40` → `20` 会自动纠正成 20-40**
- 超过总数时按总数处理（比如只有 50 张，填 `1` → `999` 就是 1-50）

### 注意

- 图片按 EXIF 方向自动转正（手机拍的竖图不会躺下），统一转成 RGB 三通道。
- 某张图读失败（文件损坏 / 格式不支持）**不会打断队列**：会输出一张 64×64 灰图占位，
  失败原因写在状态里，队列继续往下跑。
- 拖拽区拦住了 `drop` 冒泡，图片拖到节点上不会被 ComfyUI 当成工作流 JSON 解析。

## 节点：PromptVault 数据源（4 个）

分类：`dogking-tools`

不用再导出文件：**直接从 PromptVault 桌面应用实时拉数据**。在 PromptVault 里改提示词、
新建分类、加图，节点下一次执行立刻就能拿到。

> **PromptVault 必须开着。** 关掉之后节点会提示
> `PromptVault 未运行（试过 8765-8775），请先打开 PromptVault` —— 不抛异常、不打断队列，
> 已连线的图片口会输出 64×64 灰图占位，不会让下游节点崩。

### 四个节点

| 节点 | 用途 | 输出口 |
| --- | --- | --- |
| **PromptVault 图片+提示词（dogking-tools）** | 选图 + 取它的提示词 | **图片 / 提示词** |
| **PromptVault 词库（dogking-tools）** | LORA 触发词 / 编辑指令 / LLM 系统提示词 | **内容** |
| **PromptVault 资产图（dogking-tools）** | 选 1 张资产图 | **图片** |
| **PromptVault 资产图批量选择（dogking-tools）** | 选多张资产图，每张一个输出口 | **图1 … 图9**（无固定口） |

> 输出口已按需求精简：负向 / 参数 / 序号 / 总数 / 状态这些**不再占输出口**。
> 状态提示（`超 8 张` / `N 张已失效` / `短边 → 尺寸`）改由节点底部的状态条显示。

### 内嵌面板（4 个节点共用）

拖出节点就带一个 600px 高的面板，**直接在节点里点选**，不用记分类路径：

| 操作 | 说明 |
| --- | --- |
| **展开 / 收起面板** | 按钮切换。收起后节点只剩状态条（`已选 4 张：正面 / 侧面 …`） |
| **拖动节点右下角** | 面板高度**跟着变**（拖多大就多大，最小 180px），网格能一屏看更多 |
| **分页** | 首页 / 上一页 / 下一页 / 末页，每页 20 / 40 / 80 可选 |
| **搜索** | 300ms 防抖；图片匹配名称 + 提示词正文，资产图匹配名称 / 分类 / 项目 / 备注 |
| **点选** | 点卡片切换选中态；Shift 连选区间；跨页保留 |
| **图片显示** | 缩略图按 `contain` 完整显示（不裁切），非正方形的图四周会有留白 |
| **清空 / 取消 / 确定** | 见下表。**点选只是草稿，点「确定」才写回节点** |
| **随机多选** | 工具条「随机抽 N 张」，N 由节点上的「随机数量」决定（**上限 200**） |
| **删除单张** | 选定态里每张有「移除」；删中间项会弹确认框（见常见问题） |

**底部按钮：只有节点 4 有「确定」**

| 节点 | 底栏 | 点选后 |
| --- | --- | --- |
| 节点 1 / 2 / 3 | 只有「清空」 | **立即生效**（写回节点） |
| **节点 4（批量选择）** | 清空 / 取消 / 确定 | 只是草稿，点「确定」才生效 |

节点 4 单独要确认，是因为它是**动态输出口** —— 每张图占一个口，点一下就写回会让
输出口跟着疯狂增删，连带断掉用户已经连好的下游连线。其余三个节点只吐固定数量的口，
实时写回没有副作用。

> 按钮已加大（32px 高、最小宽 72px），不容易点空。

**选定状态（点确定之后）**

- **节点 3**：网格收起，只显示已选的那张大图（**加载原图，不是缩略图**），
  图片区占面板高度约 **90%**（名称 / 尺寸 / 「更改图片」压在同一行，不浪费垂直空间）。
  点「更改图片」→ 回网格并进入**替换模式**（工具条提示「点一张替换当前图片」），
  点任意一张 → **直接替换并回到预览态**，不用自己找「哪张是当前选中的」。
- **节点 4**：网格收起，显示已选卡片（每张 **229×229** + 左上角序号 + 名称，
  比网格里的 96px 大一倍多，方便核对），
  每张下面两个按钮：
  - **更换** —— 只替换这一张：回网格 → 顶部提示 `正在替换第 2 张，点一张替换`
    → 点任意一张 → 只换第 2 张，其他不动，输出口数量不变
  - **移除** —— 删掉这一张（删中间项会弹前移确认）
  底部「**重新选择**」→ **清空已选**并回网格重挑（widget、输出口、面板选中三处一起清），
  同时退出替换模式、工具条恢复成正常的筛选面包屑。

### 节点 1：图片+提示词

**参数**

| 参数 | 说明 |
| --- | --- |
| 服务地址 | 留空 = 自动发现（探 `8765-8775`）；也可填 `127.0.0.1:8766` 强制指定 |
| 分类 | 一级分类；「全部」= 不筛选。**选一级会自动包含其下所有二级分类的图** |
| 二级分类 | 只显示叶子名（`写实摄影`）；面板工具条显示完整路径（`风格 / 写实摄影`） |
| 选择模式 | `单选` / `批量选` / `随机多选` |
| 输出方式 | `一次性全部输出`（一次吐整个 batch）/ `排队输出`（每次一张） |
| 随机数量 | 1–200，默认 4，仅「随机多选」可见 |
| 自动连续 | 排队输出时，每跑完一张自动排下一次队列 |
| 已选 | 隐藏字段，随工作流保存，**不要手改** |

**选择模式决定哪些参数可见**

| 选择模式 | 输出方式 | 随机数量 | 自动连续 |
| --- | --- | --- | --- |
| 单选 | 隐藏 | 隐藏 | 隐藏 |
| 批量选 | 显示 | 隐藏 | 排队时显示 |
| 随机多选 | 显示 | 显示 | 排队时显示 |

**一次性输出的上限是 32 张**（32 × 1024² × 3 × 4B ≈ 400MB，8G 显存安全）。
超过 32 张会**自动降级为排队输出**，并在状态条里明确告知：

```
清单 50 张超过一次性输出上限（32），已自动改为排队输出（本次输出第 1 张）
```

不静默切换、不截断、不报错拒绝执行。

尺寸不一致时以**第 1 张**的宽高为基准做 letterbox（等比缩放 + 居中补边）。
填充用的是**边缘像素复制**而不是黑边 —— 纯黑是高对比区域，下游 VAEEncode / IPAdapter
会把黑条当图像内容编码进 latent。补过边的张数会写进状态：`12 张已补边对齐到 1024×1536`。

### 节点 2：词库

参数只有三个：**服务地址 / 数据源 / 已选**。

词库**没有分类维度**（LORA 触发词、编辑指令、系统提示词都是平铺的），所以不做两级联动。
面板是卡片视图，正文为空时显示「（无触发词）」。

**只能单选**。万一清单里有多条，状态条会说明
`词库节点仅支持单选，已取第 1 条（共选 2 条）`，不会静默截断。

### 节点 3：资产图（单张）

参数：**服务地址 / 项目 / 分类 / 短边尺寸 / 已选**。

「项目」在「分类」**上面**：先选项目，再看这个项目下有哪些分类。

资产图只有 `分类` / `项目` 两个**平级字符串维度**（不是两级分类），所以是两个独立下拉、
互不联动。「项目」里的 `未分项目` 表示没有填项目的资产图。

面板是**两态**：网格选择 → 点「确定」→ 预览（大图 + 名称 + 尺寸），
点「更改图片」回网格。详见上面的「选定状态」。

### 节点 4：资产图批量选择（动态输出口）

参数：**服务地址 / 项目 / 分类 / 短边尺寸 / 已选**。

和节点 3 一致：**「项目」在「分类」上面** —— 先选项目，再看这个项目下有哪些分类。

**8 个口全是图片口，没有固定口**（名称 / 总数 / 状态已删，「输出模式」也删了 ——
只剩独立输出口一种行为）：

`图1` / `图2` / … / `图9`，
按已选数量增删（最多 9 个），每口输出 `[1,H,W,3]`，各自保持原尺寸。

每个口的标签是 `图N · 名称前8字`（如 `图2 · 角色四视图-侧面`），不用去数序号。

选超过 9 张时只填前 9 个口，状态条提示
`已选 12 张（只输出前 9 张）`。

**确定后进选定状态**，可以只改其中一张 —— 见上面「选定状态」。

### 「项目 / 分类」下拉的选项从哪来（节点 3 / 4）

这两个下拉的选项**不是固定的**，是从你的资产图列表里聚合去重出来的 ——
PromptVault 的桥接口没有「资产分类列表」这种接口，只能拉一遍资产图再算。

所以：

| 你做了什么 | 下拉会变吗 |
| --- | --- |
| 在 PromptVault 里新建项目 / 分类 | **展开面板时自动刷新**，会变 |
| 改了某张资产图的分类 / 项目归属 | 同上 |
| 只是换选中的图 / 改短边尺寸 | 不用刷新 |

节点底部还有一个「**刷新分类**」按钮，是手动兜底 —— 面板已经展开时想强制重拉就点它。

> 刷新失败（PromptVault 没开）时会保留旧选项，不会把下拉清空。

### 短边尺寸（节点 3 / 节点 4）

| 值 | 行为 |
| --- | --- |
| `0` | 输出原图，不缩放 |
| `1024`（**默认**） | 短边缩到 1024，长边等比 |
| 其他 `>0` | 把**短边**缩放到该值，长边等比，**不裁切、不补边** |

> 默认 1024 是因为下游大多按 1024 级别工作，4K 原图直接喂进去又慢又吃显存。
> 要原图填 `0`。

例：`3840×2160` 的图填 `1024` → 输出 `1820×1024`。

节点 4 选多张不同尺寸的图时，**每张各自缩到短边 N，保持各自的宽高比**
（不是统一成一个尺寸 —— 统一意味着拉伸或裁切，两者都会毁图）。

状态条会写明实际结果：`已输出 1 张（图片 (28)） · 短边 1024 → 1820×1024`。

### 常见问题

**Q：打开工作流时面板为什么是收起的？**
A：刻意如此。打开工作流时用户只有两种动作 —— 直接跑（清单在隐藏 widget 里，收起不影响），
或者改选择（必然要点开面板）。收起正好省掉一次无用加载，也不会一次拉几十张缩略图。
状态条会显示 `已选 N 张：… · 点击展开`，点一下就能看到。

**Q：为什么删掉中间某张，断的是最后一个口的连线？**
A：输出口是**位置语义**，不是 id 语义 —— 第 i 个口装的是清单里的第 i 张。
删掉中间某张后，后面的图会**整体前移**，所以尾部那个口被移除、它的连线断开。
删除中间项时会弹确认框说明这一点；删最后一个则不打扰（只断它自己）。

**Q：一次性输出为什么最多 32 张？**
A：显存。一张 4K 图 decode 成 float32 约 100MB，32 张已接近 3GB。超过就自动改排队输出，
状态条会说明原因。

**Q：节点报「PromptVault 未运行」怎么办？**
A：先打开 PromptVault 桌面应用。它会在 `8765-8775` 里挑一个端口开本地只读服务，节点会自动探到；
也可以在「服务地址」里手动指定。此时已连线的图片口会输出灰图占位，不会让下游节点崩。

**Q：老工作流里的 4 个 PromptVault 节点怎么变红了？**
A：v2 把旧的「提示词 / 图片 / 图片+提示词 / 词库」4 个节点**硬删**了，换成了上面这 4 个。
旧节点会显示为缺失（红色），替换成新节点重新选图即可。

## 状态存在哪

`dogking-tools/state.json`，按节点 id 记录每个节点的进度：

```json
{
  "12": { "path": "C:/.../prompts-100.txt", "mode": "全部生成", "index": 5 },
  "220": { "kind": "image", "folder": "D:/pics", "sort": "数字升序", "mode": "全部模式", "index": 5 },
  "301": { "kind": "pv2", "sel": "9f2c1a7b3e04", "index": 3, "total": 12, "ts": 1762700000 }
}
```

三类节点共用这个文件（节点 id 全局唯一，不会冲突）：提示词节点的记录**没有 `kind`**，
图片批量加载节点带 `kind: "image"`，图片+提示词节点带 `kind: "pv2"`，互不干扰。

> **`pv2` 记录里只有 12 位指纹 `sel`，没有清单本身。**
> 清单存在工作流的隐藏 widget（`已选`）里，`state.json` 只存 `sha1("|".join(ids))[:12]`，
> 用来判断「这次执行看到的清单和上次推进时是不是同一份」—— 不是就归零。
> 这样不会出现「两份真相对不上」。
>
> 指纹用的是**原始清单**（不是过滤掉失效项之后的那份），所以
> **PromptVault 里删掉某张图不会让排队进度归零**；而迭代范围用有效张数，
> 失效的图不会在尾部吐出灰帧。

重启 ComfyUI 后进度还在。换文件 / 换文件夹 / 换排序 / 换模式都会自动清零；
PromptVault 节点在**清单变了**（重新选过图）时归零。

想全部重置就删掉这个文件。
